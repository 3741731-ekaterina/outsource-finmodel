# План проекта: веб-калькулятор стоимости часа и эффекта от внедрения сервиса учета

## 1. Цель проекта

Сделать вместо Google Таблицы самостоятельный веб-калькулятор, который можно опубликовать через GitHub и Vercel.

Калькулятор должен помогать собственнику бизнеса быстро оценить:

- стоимость своего рабочего часа;
- сколько времени и денег сейчас уходит на ведение отчетов;
- сколько можно сэкономить за счет автоматизации учета;
- потенциальную экономию на расходах за счет прозрачной структуры расходов;
- накопительный эффект по месяцам за год.

Исходная таблица: https://docs.google.com/spreadsheets/d/1_frse8Ekl0yZ3WzkLpweN_MZblmARUKi0bU_mY_UNwQ/edit

## 2. Что есть в текущей Google Таблице

Таблица называется `Копия Калькулятор стоимости часа`.

В ней два листа:

- `калькулятор` - основной расчетный лист;
- `Кейс` - содержит ссылку на кейс: https://fintablo.ru/case/shipyard

Основная логика находится на листе `калькулятор`.

## 3. Структура текущего калькулятора

### Блок 1. Высвобождаем время за счет автоматизации

Входные данные:

- `Размер дивидендов ежемесячно`
  - пример из таблицы: `500 000`
- `Кол-во рабочих часов в месяце`
  - в таблице стоит формула `=40*4`
  - пример: `160`
- `Сколько времени в месяц у вас уходит на ведение отчетов`
  - пример: `20`
- `Стоимость Финтабло ежемесячно`
  - пример: `200`

Расчеты:

- `Стоимость вашего часа = Размер дивидендов ежемесячно / Кол-во рабочих часов в месяце`
- `В год уходит на ведение отчетов = Часы на отчеты в месяц * 12`
- `В рабочих днях это = Часы на отчеты в год / 8`
- `Сейчас ведение учета обходится в месяц = Часы на отчеты в месяц * Стоимость часа`
- `Сейчас ведение учета обходится в год = Стоимость часа * Часы на отчеты в месяц * 12`
- `Экономия ежемесячно = Стоимость учета сейчас в месяц - Стоимость сервиса ежемесячно`
- `Экономия в год = Экономия ежемесячно * 12`

Помесячный накопительный эффект:

- январь: `Экономия ежемесячно`
- февраль: `Январь + Экономия ежемесячно`
- далее каждый месяц прибавляется та же ежемесячная экономия;
- отдельно считается накопительная экономия на расходах.

### Блок 2. Высвобождаем деньги за счет прозрачной структуры расходов

Входные данные:

- `Ваш ежемесячный оборот`
  - пример из таблицы: `8 000 000`
- `Вероятность сокращения расходов`
  - пример из таблицы: `2%`

Расчеты:

- `Вероятная экономия на расходах = Ежемесячный оборот * Процент сокращения расходов`
- `Экономия на расходах в год = Вероятная экономия на расходах * 12`

Примечание из таблицы:

> По статистике, внедрение Финтабло позволяет сокращать расходы компаниям на 5-7%, что ведет к росту прибыли.

Сейчас в таблице для примера используется более консервативное значение `2%`.

## 4. Что нужно сделать в веб-версии

### Основной сценарий пользователя

Пользователь открывает страницу, вводит свои бизнес-показатели и сразу видит расчет:

1. Сколько стоит его час.
2. Сколько денег теряется на ручном ведении отчетов.
3. Сколько времени в год можно высвободить.
4. Какая экономия получается после внедрения сервиса.
5. Какой накопительный эффект будет по месяцам.
6. Какой потенциал экономии есть за счет сокращения расходов.

### Поля ввода

Минимальный набор полей:

- ежемесячные дивиденды собственника;
- рабочие часы в месяц;
- часы в месяц на ведение отчетов;
- ежемесячная стоимость сервиса;
- ежемесячный оборот бизнеса;
- процент потенциального сокращения расходов.

### Результаты

На экране нужно показать:

- стоимость часа собственника;
- часы на отчеты в год;
- эквивалент в рабочих днях;
- текущую стоимость ведения учета в месяц;
- текущую стоимость ведения учета в год;
- экономию в месяц после вычета стоимости сервиса;
- экономию в год;
- вероятную экономию на расходах в месяц;
- экономию на расходах в год;
- таблицу или график накопительного эффекта за 12 месяцев.

## 5. Рекомендуемый формат реализации

Лучший вариант для публикации через GitHub и Vercel:

- стек: `Next.js` или `Vite + React`;
- язык: `TypeScript`;
- расчеты вынести в отдельный модуль, например `src/lib/calculate.ts`;
- интерфейс сделать как одну страницу-калькулятор;
- хранение данных на первом этапе не нужно;
- Google Таблица после переноса не нужна для работы калькулятора.

Для простого MVP достаточно `Vite + React`, потому что проект выглядит как интерактивная одностраничная форма без серверной логики.

Если позже понадобится SEO, блог, кейсы, заявки и интеграция с CRM, лучше сразу брать `Next.js`.

## 7. Логика расчетов для переноса в код

```ts
type CalculatorInput = {
  monthlyDividends: number;
  workingHoursPerMonth: number;
  reportHoursPerMonth: number;
  serviceCostPerMonth: number;
  monthlyRevenue: number;
  expenseReductionRate: number;
};

type CalculatorResult = {
  ownerHourlyRate: number;
  reportHoursPerYear: number;
  reportWorkDaysPerYear: number;
  currentAccountingCostPerMonth: number;
  currentAccountingCostPerYear: number;
  timeSavingPerMonth: number;
  timeSavingPerYear: number;
  expenseSavingPerMonth: number;
  expenseSavingPerYear: number;
  monthlyCumulative: Array<{
    month: string;
    timeSaving: number;
    expenseSaving: number;
    totalSaving: number;
  }>;
};
```

Основные формулы:

```text
ownerHourlyRate = monthlyDividends / workingHoursPerMonth
reportHoursPerYear = reportHoursPerMonth * 12
reportWorkDaysPerYear = reportHoursPerYear / 8
currentAccountingCostPerMonth = reportHoursPerMonth * ownerHourlyRate
currentAccountingCostPerYear = currentAccountingCostPerMonth * 12
timeSavingPerMonth = currentAccountingCostPerMonth - serviceCostPerMonth
timeSavingPerYear = timeSavingPerMonth * 12
expenseSavingPerMonth = monthlyRevenue * expenseReductionRate
expenseSavingPerYear = expenseSavingPerMonth * 12
```

## 8. Важные продуктовые решения

Перед разработкой желательно уточнить:

- как правильно написать название сервиса в интерфейсе: `Финтабло`, другое название или без бренда;
- нужно ли собирать заявки после расчета;
- нужна ли кнопка `Получить консультацию`;
- нужно ли сохранять результаты пользователя;
- нужен ли PDF/скриншот результата;
- какой процент сокращения расходов показывать по умолчанию: `2%`, `5%` или диапазон `5-7%`;
- нужно ли показывать ссылку на кейс `shipyard` в результатах.

## 9. Этапы работы

### Этап 1. Подготовка проекта

- Создать репозиторий на GitHub.
- Инициализировать проект на React/Vite или Next.js.
- Настроить TypeScript, форматирование и базовые скрипты.
- Добавить `README.md` с описанием запуска.

### Этап 2. Перенос расчетной логики

- Переписать формулы из Google Таблицы в TypeScript.
- Добавить защиту от деления на ноль.
- Добавить форматирование рублей, процентов и часов.
- Проверить расчеты на примере из таблицы:
  - дивиденды: `500 000`;
  - рабочие часы: `160`;
  - часы на отчеты: `20`;
  - стоимость сервиса: `200`;
  - оборот: `8 000 000`;
  - сокращение расходов: `2%`.

Ожидаемые результаты для проверки:

- стоимость часа: `3 125`;
- сейчас учет стоит в месяц: `62 500`;
- экономия ежемесячно: `62 300`;
- экономия в год: `747 600`;
- экономия на расходах в месяц: `160 000`;
- экономия на расходах в год: `1 920 000`.

### Этап 3. Интерфейс калькулятора

- Сделать форму ввода.
- Сделать блок с ключевыми результатами.
- Сделать помесячную таблицу или график.
- Сделать адаптивную верстку для телефона и компьютера.
- Добавить понятные подписи и подсказки к полям.

### Этап 4. Проверка

- Сверить результаты веб-калькулятора с Google Таблицей.
- Проверить крайние случаи:
  - пустые поля;
  - нули;
  - очень большие суммы;
  - процент `0%`;
  - стоимость сервиса больше текущей стоимости ручного учета.
- Проверить отображение на мобильном экране.

### Этап 5. Публикация

- Залить код в GitHub.
- Подключить репозиторий к Vercel.
- Настроить автоматический деплой при push в основную ветку.
- Получить публичную ссылку Vercel.
- При необходимости подключить домен.

## 10. Риски и нюансы

- В таблице есть опечатки в текстах: `ежемесяный`, `оброт`, `Октярь`. В веб-версии нужно исправить.
- Формула экономии времени вычитает стоимость сервиса из текущей стоимости ручного учета. Если стоимость сервиса больше текущей стоимости учета, результат может стать отрицательным. Нужно решить, показывать отрицательную экономию честно или выводить предупреждение.
- В таблице заявлен ориентир сокращения расходов `5-7%`, но в расчете стоит `2%`. В интерфейсе лучше объяснить это как консервативный сценарий или дать пользователю выбрать процент.
- Нужно аккуратно формулировать обещания экономии: лучше говорить `потенциальная`, `вероятная`, `расчетная`, а не гарантированная экономия.

Первая версия должна включать:

- одну публичную страницу;
- шесть полей ввода;

- блок `Ваш результат`;
- таблицу накопительной экономии за 12 месяцев;
- ссылку или кнопку на консультацию;
- публикацию на Vercel.

После MVP можно добавить:

- график накопительной экономии;
- переключатель сценариев: консервативный, средний, оптимистичный;
- сохранение результата в URL;
- отправку заявки;
- генерацию PDF-отчета;
- отдельный блок с кейсом.

## 12. Итоговый вывод

Да, этот калькулятор можно сделать не в Google Таблице, а как отдельный веб-сервис и опубликовать через GitHub и Vercel.

Текущая таблица хорошо подходит для переноса: формул немного, они прозрачные, серверная часть для первой версии не нужна. Основная работа - аккуратно перенести формулы, сделать удобный интерфейс и сверить результаты с исходной таблицей.
